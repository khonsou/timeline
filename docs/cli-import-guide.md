# CLI 批量导入指南（拾光轴 · Timeline Board）

> 本文档自包含：从零开始照做即可完成一次批量导入。可直接整篇粘贴到飞书文档。

## 1. 适用场景与工作原理

当你手头已经有一批内容排期数据（Excel、飞书表格、数据库导出……），不想在看板页面上逐条手敲时，用 CLI 一次性把 JSON / CSV 文件批量导入看板。

数据流：

```
┌──────────────────────┐                                ┌──────────────────────────┐
│ 你的数据文件          │  npm run import:data -- 文件   │ CLI：逐行校验 + 归一化    │
│ （.json / .csv）      │ ─────────────────────────────▶ │ （日期/指标/别名/产品目录）│
└──────────────────────┘                                └────────────┬─────────────┘
                                                                     │ 写出
                                                                     ▼
┌──────────────────────┐   发现 importedAt 变化 → 接管并    ┌──────────────────────────┐
│ 看板页面              │ ◀─ 覆写 localStorage ──────────  │ public/data/board.json   │
│ （刷新或重新打开）     │                                  │ { items, orders,         │
└──────────────────────┘                                  │   products?, importedAt }│
                                                          └──────────────────────────┘
```

数据优先级（高 → 低）：

1. **`board.json`**：每次导入生成新的 `importedAt` 时间戳；页面启动/刷新时发现 `importedAt` 与上次记录不同，就用文件数据**接管并覆写** localStorage。
2. **localStorage**（`timeline-board-v4`）：页面上的一切编辑实时保存在这里。文件没变化时，刷新以这里为准（即：导入后在页面上的修改不会因为刷新而丢）。
3. **首次启动引导卡**：以上两者都没有时，今天列出现两张引导卡。

⚠️ 关键推论：**再次运行导入命令 = 生成新 `importedAt` = 下一次刷新会用文件数据覆盖你在页面上做过的编辑**。页面编辑想保留，就不要重跑导入；或者先把页面数据当作准、文件数据当作初始快照。

## 2. 环境准备

- Node.js **20 或更高版本**（`node -v` 确认；CLI 无第三方依赖）
- 已 clone/打开项目，并在项目根目录执行过：

```bash
cd timeline-board     # 进到项目根目录（package.json 所在处）
npm install           # 首次需要
```

后文所有命令都在 `timeline-board/` 目录下执行。

## 4. 命令与参数

```bash
npm run import:data -- <文件.json|文件.csv> [--dry-run] [--merge] [--strict]
```

| 参数 | 行为 |
|---|---|
| `<文件>` | 必填。`.json` 或 `.csv`；路径不存在 → 直接退出（退出码 2） |
| `--dry-run` | 只校验 + 打印报告，**不写文件**。正式导入前建议先跑一遍 |
| `--merge` | 合并进已有 `board.json`：同 id 覆盖、新 id 追加，orders 全量重算。不加则**全量替换** |
| `--strict` | 遇到第一个无效行立即非零退出；默认是跳过无效行、报告里汇总 |

退出码：

| 退出码 | 含义 |
|---|---|
| `0` | 全部行有效（写文件模式下已写出） |
| `1` | 有无效行被跳过（`--strict` 时遇第一个无效行即此码退出） |
| `2` | 参数错误 / 文件不存在 / 文件解析失败（未产生任何导入） |

## 5. 字段规范

共 9 个字段。字段口径的权威定义见 `src/types/content.ts` 的 JSDoc。

| 字段 | 类型 | 必填 | 口径与规则 | 缺失 / 空值行为 |
|---|---|---|---|---|
| `id` | string | 否 | 显式指定则原样使用；同一文件内重复 → 该行报错跳过 | 按 `标题\|类型\|publish_at\|product_id` 的 SHA-1 前 16 位生成 `auto-xxx`——同一行数据每次导入得到同一个 id，这是 `--merge` 幂等的保证 |
| `title` | string | **是** | 卡片标题；去首尾空格后必须非空 | 空 → 该行跳过 |
| `type` | 枚举 | **是** | 只能是：`图文` / `视频` / `音频` / `直播` / `数据` | 非法值 → 该行跳过 |
| `publish_at` | string | **是** | **「计划」发布时间**（不是实际发布时间）。接受 `2026-09-03T10:00`、`2026-09-03 10:00`、`2026/9/3 10:00`（可带秒），统一归一化为 `YYYY-MM-DDTHH:mm`；会校验真实日期（2 月 30 日、25 点之类被拒） | 缺失或无法解析 → 该行跳过 |
| `roi` | number \| null | 否 | 投放效率 = 发布后 7 天归因销售额 ÷ 广告花费；非负数字 | 空 → `null`；`publish_at` 在未来时强制 `null`（未发布无数据） |
| `comment` | string | 否 | 备注 / 复盘，支持多行，详情页按行展示 | 空 → `''` |
| `product_id` | string | **是** | 归属产品。内置目录 `P-1000`（看板自身）~`P-1006`；或用 JSON 包裹形式的 `products` 自带目录 | 不在目录中 → **警告但保留**，看板上降级显示原始 id |
| `propagation_4h` | number \| null | 否 | 发布后 4 小时曝光量（impressions，发布时刻起 4 小时窗口）；非负数字 | 同 `roi` |
| `engagement_4h` | number \| null | 否 | 发布后 4 小时互动量（点赞+评论+分享+收藏之和，同 4h 窗口）；非负数字 | 同 `roi` |

**中文字段名别名**（JSON 的键、CSV 的表头都可用，导入时自动映射）：

| 中文 | 英文字段 |
|---|---|
| 标题 | `title` |
| 类型 | `type` |
| 计划发布时间 | `publish_at` |
| 备注 | `comment` |
| 产品ID | `product_id` |
| ROI | `roi` |
| 曝光4h | `propagation_4h` |
| 互动4h | `engagement_4h` |

注意：`id` 没有中文别名；数字字段在 CSV 里天然是文本，CLI 会自动转数值（`"3.8"` 与 `3.8` 等价），空单元格 = `null`。

## 6. 文件格式

### 6.1 JSON：裸数组（最简单）

```json
[
  {
    "title": "键盘配色投票图文",
    "type": "图文",
    "publish_at": "2026-08-10 09:20",
    "product_id": "P-1001",
    "roi": 2.9,
    "comment": "投票互动超预期，加做一期",
    "propagation_4h": 31200,
    "engagement_4h": 4100
  },
  {
    "title": "耳机联名预告海报",
    "type": "图文",
    "publish_at": "2026-09-14T12:00",
    "product_id": "P-1002"
  }
]
```

### 6.2 JSON：`{ items, products }` 包裹（可自带产品目录）

```json
{
  "products": [
    { "id": "P-2001", "name": "极光机械键盘 Pro" },
    { "id": "P-2002", "name": "深海降噪耳机" }
  ],
  "items": [
    {
      "id": "row-001",
      "title": "极光键盘 Pro 开箱视频",
      "type": "视频",
      "publish_at": "2026-09-05T19:30",
      "product_id": "P-2001",
      "roi": null,
      "comment": "",
      "propagation_4h": null,
      "engagement_4h": null
    }
  ]
}
```

`products` 会接管看板的产品目录（刷新后产品选择器里就是这些名字）；不带 `products` 则用内置目录。完整示例见 `examples/import-sample.json`。

### 6.3 CSV（飞书/Excel 导出首选）

首行表头，中英文均可；解析遵循 RFC4180：字段含逗号/换行/引号时用双引号包裹，字段内的引号写成两个（`""`）：

```csv
标题,类型,计划发布时间,ROI,备注,产品ID,曝光4h,互动4h
键盘配色投票图文,图文,2026-08-10 09:20,2.9,"投票互动超预期,加做一期",P-1001,31200,4100
耳机使用场景短片,视频,2026-08-22 12:45,1.7,,P-1002,19800,1500
"台灯开箱,含字幕",视频,2026-09-01 18:00,3.3,"标题带逗号的 CSV 转义演示",P-1004,67800,5900
```

导出注意事项：

- **编码必须 UTF-8**。文件带 BOM 也能正常解析（已兼容）；Excel 请选「CSV UTF-8（逗号分隔）(*.csv)」另存，不要用默认的「CSV（逗号分隔）」（那是本地编码，会乱码）。
- 日期列不要被 Excel 格式化成 `2026/9/3 上午10:00` 这类带上午/下午的文本——只认 24 小时制（对照表见 FAQ-4）。
- 空单元格 = 该字段为空（指标置 `null`、备注置空串）。

## 7. 导入后会发生什么

- **看板日期窗口自动扩展**：默认窗口是今天 ±14 天；导入的数据超出窗口时，日列自动扩到数据的最早/最晚日期，历史与未来内容都有列可归。
- **未发布内容指标强制置 null**：`publish_at` 晚于当前时间的行，三个指标一律置 `null`（卡面显示「待发布」虚线占位），报告里会提示条数。把计划时间改到过去即可在详情页录入数据。
- **未知 product_id**：警告但保留，卡片上降级显示原始 id 文本；把该 id 补进产品目录（或修正文件）后即恢复正常显示。
- **自定义产品目录**：JSON 包裹形式的 `products` 会随导入生效，详情页的「归属产品」选择器随之更新。
- **与页面编辑的关系**：接管瞬间会用文件数据覆写 localStorage；之后你在页面上的编辑存 localStorage，刷新不丢——**除非你再次运行导入**（新 `importedAt` 会再次接管并覆盖）。

## 8. 校验规则速查

以下情况的行会被**跳过**（其余行照常导入，报告逐行列出原因；`--strict` 时遇第一处即退出码 1 停止）：

| 规则 | 报错示例 |
|---|---|
| `title` 为空 | `title 必填且非空` |
| `type` 不在 5 类枚举内 | `type 非法: "短视频"，合法值: 图文 / 视频 / 音频 / 直播 / 数据` |
| `publish_at` 缺失或解析失败 | `publish_at 无法解析: "下周三"（接受 YYYY-MM-DDTHH:mm / YYYY-MM-DD HH:mm / YYYY/M/D H:mm）` |
| 同一文件内 `id` 重复 | `id 重复: row-001` |
| `product_id` 为空 | `product_id 必填且非空` |
| 指标不是非负数字 | `roi 须为空或非负数字，得到 "abc"` |

报错读法（真实输出示例）：JSON 按「第 N 条」（从 1 数）、CSV 按「第 N 行」（含表头，即数据第 1 行 = 第 2 行）：

```
总条数: 4 | 有效: 1 | 跳过: 3
  ✗ 第 2 条: title 必填且非空
  ✗ 第 3 条: type 非法: "短视频"，合法值: 图文 / 视频 / 音频 / 直播 / 数据
  ✗ 第 4 条: publish_at 无法解析: "下周三"（接受 …）
```

## 9. 常见问题 FAQ

**Q1：导入成功了，页面却没变化？**
先**刷新页面**（接管发生在刷新/重新打开时）。刷新后仍旧：① 确认命令真的写出了文件（报告末尾应有 `✓ 已写出: public/data/board.json`）；② 如果你手动删除过 `public/data/board.json`，dev server 对 `public/` 有进程级缓存——重启 `npm run dev` 再刷新；③ 浏览器开了多个看板标签页时，全部刷新。

**Q2：再次运行导入，会覆盖我在页面上改过的内容吗？**
会。每次导入生成新 `importedAt`，页面下次刷新即被文件数据接管覆写。页面上的编辑想长期保留，就不要重跑导入；文件只当初始快照用。

**Q3：想清空看板、恢复最初的两张引导卡？**
两步都要做：① 删除 `public/data/board.json`（否则刷新又被文件接管；dev server 运行中删文件需重启 `npm run dev`）；② 浏览器 DevTools → Console 执行 `localStorage.clear()`（或 Application → Storage → Clear site data），再刷新。另外：在页面上把卡片逐张删光是合法状态，刷新不会复活引导卡。

**Q4：`publish_at` 老报「无法解析」？写法对照：**

| 写法 | 是否接受 |
|---|---|
| `2026-09-03T10:00` | ✅（归一化目标格式） |
| `2026-09-03 10:00`、`2026/9/3 10:00` | ✅（自动归一化） |
| `2026-09-03 10:00:30`（带秒） | ✅（秒被忽略） |
| `2026-9-3`（缺时间） | ❌ 必须带时分 |
| `下周三` / `9月3日上午10点` | ❌ 只认 24 小时制数字写法 |
| `2026-02-30T10:00` | ❌ 非真实日期 |

**Q5：`--merge` 重复导入同一个文件会产生重复卡片吗？**
不会。缺失的 id 按「标题|类型|publish_at|product_id」内容哈希确定性生成，同一份文件每次导入得到同一批 id，`--merge` 下同 id 只覆盖不新增（实测：同一示例 CSV 连导两次，仍是 8 条）。

**Q6：JSON 里把数字写成了字符串（`"roi": "3.8"`）要紧吗？**
不要紧，`"3.8"` 会被当数字 3.8 接受；空字符串 `""` 视同 `null`。但 `"abc"`、`"高"` 这类转不成数字的值会让该行被跳过（报错：`须为空或非负数字`）。

**Q7：Excel / 飞书表格导出的 CSV 打开乱码或首列表头解析失败？**
乱码 = 编码不是 UTF-8：Excel 用「另存为 → CSV UTF-8（逗号分隔）」；飞书表格「下载为 CSV」默认即 UTF-8。UTF-8 带 BOM 的文件 CLI 已兼容，无需手工处理。

**Q8：担心导错，能先预演吗？**
能，而且建议：先 `npm run import:data -- 你的文件 --dry-run`，报告会列出有效/跳过条数、逐行原因、日期分布、未发布条数，**不写任何文件**；确认无误后去掉 `--dry-run` 正式导入。
