# CLI 批量导入指南（拾光轴 · Timeline Board）

> 本文档自包含：从零开始照做即可完成一次批量导入。可直接整篇粘贴到飞书文档。

> ⚠️ **v15 注记（多用户看板服务）**：v15 起看板数据存服务端 SQLite，`board.json` **不再接管在线看板**。CLI 的位置变为：导入生成的 `board.json` 是首页新建看板时**「从本机现有数据初始化」**的种子——跑完 CLI → 打开首页 → 勾选初始化（默认已勾）→ 新建看板，数据即进新板。已有的在线看板不受 CLI 影响；要更新已有看板，用看板页顶栏「导入」按钮做页面内增量导入（与 CLI 同一套校验合并语义）。下文的数据流与优先级描述已按 v15 口径更新。

## 1. 适用场景与工作原理

当你手头已经有一批内容排期数据（Excel、飞书表格、数据库导出……），不想在看板页面上逐条手敲时，用 CLI 一次性把 JSON / CSV 文件批量导入看板。

数据流（v15）：

```
┌──────────────────────┐                                ┌──────────────────────────┐
│ 你的数据文件          │  npm run import:data -- 文件   │ CLI：逐行校验 + 归一化    │
│ （.json / .csv）      │ ─────────────────────────────▶ │ （日期/指标/别名/产品目录）│
└──────────────────────┘                                └────────────┬─────────────┘
                                                                     │ 写出
                                                                     ▼
┌──────────────────────┐   首页新建看板 → 勾选          ┌──────────────────────────┐
│ 新看板（服务端）      │ ◀─「从本机现有数据初始化」────  │ public/data/board.json   │
│ 列表页 / → /b/:id     │   （默认勾选，一次性种子）      │ { items, orders,         │
└──────────────────────┘                                  │   products?, members?,   │
                                                          │   importedAt }           │
                                                          └──────────────────────────┘
```

初始化时的数据选取（高 → 低）：

1. **v14 及之前的单板 localStorage 四键**（`timeline-board-v4` / `:products` / `:members`）：老用户升级后的本机数据优先作为种子。
2. **`board.json`**：无 localStorage 数据时采用。两种形态：`{ items, orders, products?, members?, importedAt }` → items/orders 全量采用，products/members 在内置目录基础上**差分合并**；`{ products, importedAt }`（独立产品导入产物，无 items 键）→ 初始化为「只带产品目录 + 两张引导卡」的新板。
3. **引导卡**：以上两者都没有时，新板今天列出现两张引导卡（初始化勾选框同时禁用）。

⚠️ 关键推论（v15）：CLI 可以反复跑，`board.json` 只会越攒越全（产品/成员目录恒为差分累积）；它只影响**之后新建的看板**，绝不会覆盖任何已有看板的内容。已有看板的增量导入请用看板页顶栏「导入」。

## 2. 环境准备

- Node.js **20 或更高版本**（`node -v` 确认；CLI 无第三方依赖）
- 已 clone/打开项目，并在项目根目录执行过：

```bash
cd timeline-board     # 进到项目根目录（package.json 所在处）
npm install           # 首次需要
```

后文所有命令都在 `timeline-board/` 目录下执行。

## 3. 快速开始（30 秒跑通）

用仓库自带的示例文件试一次完整流程。**推荐两步走：先导入产品目录，再导入内容卡片**——这样卡片里的 `product_id`（P-200x 系列）都能命中目录；就算没命中，v13 起也会按卡片行的 `product_name`（缺省用 id 占位）自动登记为新产品，不再显示「不明」：

```bash
# 第 1 步：导入产品目录（P-2001~P-2005，只动目录、不动内容卡片）
npm run import:data -- --products examples/products-sample.csv

# 第 2 步：导入内容卡片
```

## 4. 命令与参数

```bash
npm run import:data -- <文件.json|文件.csv> [--dry-run] [--merge] [--strict]
npm run import:data -- --products <产品文件.json|产品文件.csv> [--dry-run] [--merge] [--strict]
```

| 参数 | 行为 |
|---|---|
| `<文件>` | 必填。`.json` 或 `.csv`；路径不存在 → 直接退出（退出码 2） |
| `--products` | 独立产品目录导入：`<文件>` 改指**产品文件**（不与 items 文件混用）。只接管产品目录、不动内容卡片。格式与落地语义详见第 7 节 |
| `--dry-run` | 只校验 + 打印报告，**不写文件**。正式导入前建议先跑一遍 |
| `--merge` | 合并进已有 `board.json`：同 id 覆盖、新 id 追加，orders 全量重算。不加则**全量替换**（`--products` 模式下为兼容保留：v13 起产品目录恒为差分合并，见第 7 节） |
| `--strict` | 遇到第一个无效行立即非零退出；默认是跳过无效行、报告里汇总 |

退出码：

| 退出码 | 含义 |
|---|---|
| `0` | 全部行有效（写文件模式下已写出） |
| `1` | 有无效行被跳过（`--strict` 时遇第一个无效行即此码退出） |
| `2` | 参数错误 / 文件不存在 / 文件解析失败（未产生任何导入） |

## 5. 字段规范

共 12 个字段。字段口径的权威定义见 `src/types/content.ts` 的 JSDoc。

| 字段 | 类型 | 必填 | 口径与规则 | 缺失 / 空值行为 |
|---|---|---|---|---|
| `id` | string | 否 | 显式指定则原样使用；同一文件内重复 → 该行报错跳过 | 按 `标题\|类型\|publish_at\|product_id` 的 SHA-1 前 16 位生成 `auto-xxx`——同一行数据每次导入得到同一个 id，这是 `--merge` 幂等的保证 |
| `title` | string | **是** | 卡片标题；去首尾空格后必须非空 | 空 → 该行跳过 |
| `type` | 枚举 | **是** | 只能是：`图文` / `视频` / `音频` / `直播` / `数据` | 非法值 → 该行跳过 |
| `publish_at` | string | **是** | **「计划」发布时间**（不是实际发布时间）。接受 `2026-09-03T10:00`、`2026-09-03 10:00`、`2026/9/3 10:00`（可带秒），统一归一化为 `YYYY-MM-DDTHH:mm`；会校验真实日期（2 月 30 日、25 点之类被拒） | 缺失或无法解析 → 该行跳过 |
| `status` | 枚举 | 否 | 内容状态，只能是：`待执行` / `待发布` / `已发布`（存中文字符串）。**状态是指标的开关**：非 `已发布` → 三个指标强制 `null` | 空 → 按 `publish_at` 推导（未来 → `待发布`，否则 → `已发布`，与旧版按时间口径一致）；非法值 → 该行跳过（`status 非法: "x"，合法值: 待执行 / 待发布 / 已发布`）。显式填 `已发布` 可为未来日期的卡片解锁指标录入 |
| `roi` | number \| null | 否 | 投放效率 = 发布后 7 天归因销售额 ÷ 广告花费；非负数字 | 空 → `null`；`status ≠ 已发布` 时强制 `null`（未发布无数据，按状态而非按时间判定） |
| `comment` | string | 否 | 备注 / 复盘，支持多行，详情页按行展示 | 空 → `''` |
| `product_id` | string | 否 | 归属产品。在当前产品目录（=应用内产品状态，初始仅内置 `P-1000` 光轴，可被导入差分合并、可在页面「产品管理」增删改）中命中 → 显示产品名 | 缺失/空 → 置 `''`（未归属，显示「不明」，报告汇总条数，**不跳行**）；不在目录 → **自动登记为新产品**（随行 `product_name` 作名，缺省用 id 占位，报告汇总「自动登记新产品: N 个」） |
| `product_name` | string | 否 | 卡片行可选携带的产品名：**仅当 `product_id` 不在目录时生效**，作为自动登记新产品的名称；同 id 多行取第一个非空值；文件内嵌 `products` 中已有的 id 不重复收集（内嵌优先） | 空 → 以 `product_id` 占位作名（占位名可在「产品管理」改名；占位名永远不覆盖已有真实名称） |
| `content_owner` | string | 否 | 内容负责人，**按姓名填写**（不是 id）。姓名在当前成员目录（=应用内成员状态，初始内置 `M-1001 林晓` / `M-1002 陈远`）命中 → 复用既有 id；未知名 → **自动登记为新成员**（id 自动取 `M-<最大编号+1>`，报告汇总「自动登记新成员: N 个」） | 空 → 置 `''`（未分配，不警告不跳行，详情页显示「未分配」） |
| `delivery_owner` | string | 否 | 投放负责人，规则与 `content_owner` 完全相同 | 同 `content_owner` |
| `propagation_4h` | number \| null | 否 | 发布后 4 小时曝光量（impressions，发布时刻起 4 小时窗口）；非负数字 | 同 `roi` |
| `engagement_4h` | number \| null | 否 | 发布后 4 小时互动量（点赞+评论+分享+收藏之和，同 4h 窗口）；非负数字 | 同 `roi` |

**中文字段名别名**（JSON 的键、CSV 的表头都可用，导入时自动映射）：

| 中文 | 英文字段 |
|---|---|
| 标题 | `title` |
| 类型 | `type` |
| 计划发布时间 | `publish_at` |
| 状态 | `status` |
| 备注 | `comment` |
| 产品ID | `product_id` |
| 产品名 / 产品名称 | `product_name` |
| 内容负责人 | `content_owner` |
| 投放负责人 | `delivery_owner` |
| ROI | `roi` |
| 曝光4h | `propagation_4h` |
| 互动4h | `engagement_4h` |

注意：`id` 没有中文别名；数字字段在 CSV 里天然是文本，CLI 会自动转数值（`"3.8"` 与 `3.8` 等价），空单元格 = `null`。

## 6. 文件格式

### 6.1 JSON：裸数组（最简单）

```json
[
  {
    "title": "键盘配色投票图文",
    "type": "图文",
    "publish_at": "2026-08-10 09:20",
    "product_id": "P-2001",
    "roi": 2.9,
    "comment": "投票互动超预期，加做一期",
    "propagation_4h": 31200,
    "engagement_4h": 4100
  },
  {
    "title": "耳机联名预告海报",
    "type": "图文",
    "publish_at": "2026-09-14T12:00",
    "product_id": "P-2002"
  }
]
```

### 6.2 JSON：`{ items, products }` 包裹（可自带产品目录）

```json
{
  "products": [
    { "id": "P-2001", "name": "极光机械键盘 Pro" },
    { "id": "P-2002", "name": "深海降噪耳机" }
  ],
  "items": [
    {
      "id": "row-001",
      "title": "极光键盘 Pro 开箱视频",
      "type": "视频",
      "publish_at": "2026-09-05T19:30",
      "product_id": "P-2001",
      "roi": null,
      "comment": "",
      "propagation_4h": null,
      "engagement_4h": null
    }
  ]
}
```

`products` 会差分合并进看板的产品目录（刷新后产品选择器里就是这些名字）；不带 `products` 则**沿用当前目录**（CLI 会把已有 `board.json` 里的 products 结转到新文件，不会回落重置）。完整示例见 `examples/import-sample.json`（其中 imp-0009 一次演示三件事：卡片行携带 `product_name` 自动登记新产品；显式 `"status": "已发布"` 为未来日期（2026-09-18）解锁指标录入；内容负责人填未知姓名「苏晴」自动登记为新成员 M-1003）。

### 6.3 CSV（飞书/Excel 导出首选）

首行表头，中英文均可；解析遵循 RFC4180：字段含逗号/换行/引号时用双引号包裹，字段内的引号写成两个（`""`）：

```csv
标题,类型,计划发布时间,状态,ROI,备注,产品ID,产品名称,曝光4h,互动4h,内容负责人,投放负责人
键盘配色投票图文,图文,2026-08-10 09:20,,2.9,"投票互动超预期,加做一期",P-2001,,31200,4100,林晓,陈远
"台灯开箱,含字幕",视频,2026-09-01 18:00,,3.3,"标题带逗号的 CSV 转义演示",P-2003,,67800,5900,陈远,林晓
曜岩键盘新品预热视频,视频,2026-09-18 10:00,,,新产品自动登记演示,P-2100,曜岩客制化键盘,,,苏晴,陈远
```

第二行演示引号转义（标题/备注含逗号）；第三行演示两列：`产品名称` 列——P-2100 不在目录中，导入时自动登记为新产品「曜岩客制化键盘」（留空则以 id 占位登记）；`内容负责人` 列——苏晴不在成员目录中，按姓名自动登记为新成员（林晓/陈远是内置成员，直接复用既有 id）。`状态` 列留空 = 按 `publish_at` 推导（未来 → 待发布，否则已发布）。

导出注意事项：

- **编码必须 UTF-8**。文件带 BOM 也能正常解析（已兼容）；Excel 请选「CSV UTF-8（逗号分隔）(*.csv)」另存，不要用默认的「CSV（逗号分隔）」（那是本地编码，会乱码）。
- 日期列不要被 Excel 格式化成 `2026/9/3 上午10:00` 这类带上午/下午的文本——只认 24 小时制（对照表见 FAQ Q4）。
- 空单元格 = 该字段为空（指标置 `null`、备注置空串）。

## 7. 独立产品列表导入（--products）

只想换产品目录、不动内容卡片时使用（例如产品线更新、先在 Excel / 飞书表格里整理好一份产品表）：

```bash
npm run import:data -- --products <产品文件.json|产品文件.csv> [--dry-run] [--merge] [--strict]
```

独立模式：`<文件>` 指**产品文件**，不与 items 文件混用；`--dry-run` / `--merge` / `--strict` 可组合，语义同 items 版。

### 7.1 产品文件格式

**JSON**：产品数组，或 `{ "products": [...] }` 包裹：

```json
[
  { "id": "P-2001", "name": "极光机械键盘 Pro" },
  { "id": "P-2002", "name": "深海降噪耳机" }
]
```

**CSV**：表头 `产品ID,产品名称`（RFC4180 解析与 items 版相同、UTF-8 / BOM 同样兼容）；表头别名：`id / 产品ID / 产品编号` → id，`name / 产品名 / 产品名称 / 名称` → name：

```csv
产品ID,产品名称
P-2001,极光机械键盘 Pro
P-2002,深海降噪耳机
```

示例文件：`examples/products-sample.csv`（P-2001~P-2005）、`examples/products-sample.json`（与 CSV 部分 id 重叠，便于演示差分合并：P-2001/P-2003 同 id 改名更新，P-2006~P-2008 新 id 追加）。

### 7.2 校验规则

| 规则 | 报错示例 |
|---|---|
| id 为空 | `产品 id 必填且非空` |
| id 文件内重复 | `产品 id 重复: P-2001` |
| name 为空 | `产品名称必填且非空` |

逐行带行号报错（CSV 按「第 N 行」含表头、JSON 按「第 N 条」），退出码语义同 items 版：全有效 `0` / 有跳过 `1` / 参数·文件·解析错误 `2`；`--strict` 遇第一处即 `1`。

### 7.3 落地语义与优先级关系（v13 差分合并）

- **心智模型：导入只能加/改产品，永不删除；删产品的唯一途径是页面「产品管理」弹窗。** 所有入口（`--products` 独立导入、items 内嵌 `products`、卡片行 `product_name` 自动登记、顶栏「导入」按钮）统一走 `mergeProducts` 差分合并：
  - 同 id 且 name 不同 → **更新**名称（计 updated）；
  - 同 id 且 name 相同 → 保留（计 unchanged）；
  - 新 id → **追加**（计 added）；
  - 现有目录中本次未提及的条目 → **原样保留**。
- 写出的 `board.json` 为 **`{ products, importedAt }`（无 items 键）**；页面刷新时发现 `importedAt` 变化 → **仅接管产品目录**，现有 items/orders 与页面上的编辑一概不动（localStorage 的产品目录同样按 `importedAt` 防重复接管）。board.json 中的 products 是 CLI 与已有 board.json 差分合并后的**累积全量**——它是全新浏览器（清空 localStorage）的唯一状态来源。
- 与 items 内嵌 `products` 的关系——同一个产品目录，后执行者覆盖先执行者（按上述差分规则）：
  - items 导入**带**内嵌 `products` → 全量接管内容，目录差分合并；
  - items 导入**不带** `products` → 目录结转：CLI 把已有 `board.json` 的 products 连同本次自动登记的新产品一起差分写出，页面侧目录只增/改不重置；
  - `--products` 独立导入 → 只动目录，永远不动内容；
  - 推论：在「产品管理」里删掉的产品，如果之后又出现在任何导入源（产品文件 / items 内嵌 / 卡片行 product_id）或已有 board.json 结转中，会被重新登记——想彻底删除，确保它不再出现在任何导入源里。
- 占位名保护：自动登记缺省名（name = id）**永远不覆盖**已有真实名称（后补的产品文件可以正常把占位名更新为真实名称，反向不行）。
- 运行时产品解析顺序：**当前产品目录（=应用内产品状态，`timeline-board-v4:products`，初始仅内置 P-1000 光轴）→「不明」**。在「产品管理」里删除被引用的产品后，引用卡片自动降级显示「不明」。

## 8. 成员目录（负责人按姓名导入，自动登记）

内容/投放负责人两列**按姓名填写**（不是 id），落地语义与产品目录同哲学但**匹配键是姓名**：

- **姓名即键**：姓名在成员目录中已存在 → 复用既有 id（同名不同 id 时永远复用既有 id，不存在「更新」维度）；未知名 → 自动登记为新成员，id 自动取 `M-<现有目录数字后缀最大值+1>`（M-1xxx 段，与目录现有 id 不冲突）；同一文件内同一未知名多行复用同一个新 id。
- **初始目录**：内置 `M-1001 林晓` / `M-1002 陈远` 两个示例成员；真实成员通过导入自动登记或页面「成员管理」进入目录。
- **累积全量写出**：CLI 把本次自动登记的新成员与已有 `board.json` 的 members 按姓名差分合并后写出（`成员目录差分：新增 N / 同名复用 M`）——board.json 是全新浏览器的唯一状态来源；页面接管时同样差分合并进本地成员目录（`timeline-board-v4:members`）。
- **导入只能加成员、永不删除；删成员的唯一途径是页面顶栏「成员管理」弹窗**（增删改、引用计数分列「内容 N · 投放 M」、新增行 id 自动生成）。推论与产品相同：在「成员管理」里删掉的成员，如果之后又出现在任何导入源或已有 board.json 结转中，会被重新登记。
- **删除被引用的成员**后，引用卡片的负责人自动降级显示「未分配」（鼠标悬停可见原始 id）；空值（未填负责人）同样显示「未分配」，不警告不跳行。
- 详情页两个负责人下拉：选项 = 当前成员目录 + 顶部固定「未分配」（选中即清空）；目录查不到的存量 id 降级显示在「未分配」项。

## 9. 导入后会发生什么

- **看板日期窗口自动扩展**：默认窗口是今天 ±14 天；导入的数据超出窗口时，日列自动扩到数据的最早/最晚日期，历史与未来内容都有列可归。
- **未发布内容指标强制置 null（v14 起按状态判定）**：`status ≠ 已发布` 的行，三个指标一律置 `null`（卡面显示对应状态的虚线占位），报告里会提示条数。`status` 缺省按 `publish_at` 推导（未来 → `待发布`，否则 → `已发布`），与旧版按时间口径一致；显式填 `已发布` 可为未来日期的卡片解锁指标录入。页面侧：详情页的「状态」三分段（待执行/待发布/已发布）点击即切换——切到非「已发布」指标立即置 null 并锁定，切回「已发布」解锁录入。
- **未归属 / 自动登记 product_id**：product_id 为空的行不再被跳过——置 `''` 并在报告汇总「未填写归属产品: N 条」，卡片显示「不明」；product_id 不在目录的行**自动登记为新产品**（随行 `product_name` 作名，缺省 id 占位），卡片直接显示产品名，报告汇总「自动登记新产品: N 个」并在差分统计中计入「新增」。占位名产品之后用产品文件 / 产品管理补上真实名称即可（占位名不会反向覆盖真实名称）。
- **负责人与成员目录**：内容/投放负责人按姓名填写，已知姓名复用既有 id、未知名**自动登记为新成员**（报告汇总「自动登记新成员: N 个」，差分统计计入「新增」），详见第 8 节；未填 → 显示「未分配」。
- **自定义产品目录**：JSON 包裹形式的 `products` 与 `--products` 独立导入都按**差分合并**生效（同 id 改名更新、新 id 追加、未提及保留，见第 7 节）。页面侧还有两个入口：顶栏「产品管理」弹窗直接增删改（删除被引用产品时引用卡片自动降级「不明」，新增行 id 自动取 `P-<最大编号+1>`）、顶栏「导入」按钮走同一套校验 + merge 语义在页面内增量导入（报告弹窗含产品差分行与成员登记行）。详情页的「归属产品」选择器随之更新（选择器顶部固定有「不明（不归属）」选项，选中即清空归属）；成员目录同理走顶栏「成员管理」弹窗（见第 8 节）。
- **与页面编辑的关系**：接管瞬间会用文件数据覆写 localStorage；之后你在页面上的编辑存 localStorage，刷新不丢——**除非你再次运行导入**（新 `importedAt` 会再次接管并覆盖）。

## 10. 校验规则速查

以下情况的行会被**跳过**（其余行照常导入，报告逐行列出原因；`--strict` 时遇第一处即退出码 1 停止）：

| 规则 | 报错示例 |
|---|---|
| `title` 为空 | `title 必填且非空` |
| `type` 不在 5 类枚举内 | `type 非法: "短视频"，合法值: 图文 / 视频 / 音频 / 直播 / 数据` |
| `publish_at` 缺失或解析失败 | `publish_at 无法解析: "下周三"（接受 YYYY-MM-DDTHH:mm / YYYY-MM-DD HH:mm / YYYY/M/D H:mm）` |
| `status` 不在 3 态枚举内 | `status 非法: "进行中"，合法值: 待执行 / 待发布 / 已发布` |
| 同一文件内 `id` 重复 | `id 重复: row-001` |
| 指标不是非负数字 | `roi 须为空或非负数字，得到 "abc"` |

> 注意：`product_id` 为空**不再是跳行级错误**——该行照常导入、置 `''`，报告里汇总「未填写归属产品: N 条（已置空，UI 显示「不明」）」。`product_id` 不在目录也不是错误——自动登记为新产品（随行 `product_name` 作名，缺省 id 占位），报告汇总「自动登记新产品: N 个」。

报错读法（真实输出示例）：JSON 按「第 N 条」（从 1 数）、CSV 按「第 N 行」（含表头，即数据第 1 行 = 第 2 行）：

```
总条数: 4 | 有效: 1 | 跳过: 3
  ✗ 第 2 条: title 必填且非空
  ✗ 第 3 条: type 非法: "短视频"，合法值: 图文 / 视频 / 音频 / 直播 / 数据
  ✗ 第 4 条: publish_at 无法解析: "下周三"（接受 …）
```

## 11. 常见问题 FAQ

**Q1：导入成功了，页面却没变化？**
先**刷新页面**（接管发生在刷新/重新打开时）。刷新后仍旧：① 确认命令真的写出了文件（报告末尾应有 `✓ 已写出: public/data/board.json`）；② 如果你手动删除过 `public/data/board.json`，dev server 对 `public/` 有进程级缓存——重启 `npm run dev` 再刷新；③ 浏览器开了多个看板标签页时，全部刷新。

**Q2：再次运行导入，会覆盖我在页面上改过的内容吗？**
会。每次导入生成新 `importedAt`，页面下次刷新即被文件数据接管覆写。页面上的编辑想长期保留，就不要重跑导入；文件只当初始快照用。

**Q3：想清空看板、恢复最初的两张引导卡？**
两步都要做：① 删除 `public/data/board.json`（否则刷新又被文件接管；dev server 运行中删文件需重启 `npm run dev`）；② 浏览器 DevTools → Console 执行 `localStorage.clear()`（或 Application → Storage → Clear site data），再刷新。另外：在页面上把卡片逐张删光是合法状态，刷新不会复活引导卡。

**Q4：`publish_at` 老报「无法解析」？写法对照：**

| 写法 | 是否接受 |
|---|---|
| `2026-09-03T10:00` | ✅（归一化目标格式） |
| `2026-09-03 10:00`、`2026/9/3 10:00` | ✅（自动归一化） |
| `2026-09-03 10:00:30`（带秒） | ✅（秒被忽略） |
| `2026-9-3`（缺时间） | ❌ 必须带时分 |
| `下周三` / `9月3日上午10点` | ❌ 只认 24 小时制数字写法 |
| `2026-02-30T10:00` | ❌ 非真实日期 |

**Q5：`--merge` 重复导入同一个文件会产生重复卡片吗？**
不会。缺失的 id 按「标题|类型|publish_at|product_id」内容哈希确定性生成，同一份文件每次导入得到同一批 id，`--merge` 下同 id 只覆盖不新增（实测：同一示例 CSV 连导两次，仍是 9 条）。产品目录同理：第二次导入时自动登记数与差分「新增/更新」均为 0。成员目录也同理：已知姓名直接复用既有 id，重复导入不会重复登记（第二次导入时「自动登记新成员」为 0、成员差分「新增」为 0）。

**Q6：JSON 里把数字写成了字符串（`"roi": "3.8"`）要紧吗？**
不要紧，`"3.8"` 会被当数字 3.8 接受；空字符串 `""` 视同 `null`。但 `"abc"`、`"高"` 这类转不成数字的值会让该行被跳过（报错：`须为空或非负数字`）。

**Q7：Excel / 飞书表格导出的 CSV 打开乱码或首列表头解析失败？**
乱码 = 编码不是 UTF-8：Excel 用「另存为 → CSV UTF-8（逗号分隔）」；飞书表格「下载为 CSV」默认即 UTF-8。UTF-8 带 BOM 的文件 CLI 已兼容，无需手工处理。

**Q8：担心导错，能先预演吗？**
能，而且建议：先 `npm run import:data -- 你的文件 --dry-run`，报告会列出有效/跳过条数、逐行原因、日期分布、未发布条数，**不写任何文件**；确认无误后去掉 `--dry-run` 正式导入。

**Q9：卡片上产品名显示「不明」是什么意思？**
三种情况：① 导入时没填 `product_id`（未归属，已置 `''`）；② 卡片的 `product_id` 在当前产品目录里查不到（v13 起**新导入**的未知 id 会自动登记，此情况只会出现在历史卡片或手工改过的 localStorage 上）；③ 产品后来在「产品管理」里被删除。卡片面与详情页统一显示淡色虚线下划线的「不明」，鼠标悬停可看到 `原始 product_id: xxx`（未归属则无原始 id）。修复：详情页「归属产品」选择器重新选择即可（顶部固定有「不明（不归属）」选项，选中即主动清空归属）；批量修复就把 id 补进产品目录（`--products` 独立导入见第 7 节，或在页面顶栏「产品管理」里新增）后刷新。
