# 决策记录（decisions）

> 只记「为什么这么做」，按主题分组，标注拍板的版本/时间。新决策追加在对应分组末尾；改变旧决策时改写条目并保留原结论作注。

## 协作与权限

- **多人协作 = LWW 后写覆盖 + 轮询同步**（v15）：接受「两人同时编辑、后者覆盖前者」；不做 websocket、不做冲突检测——团队规模下轮询（5s 带 version）足够且实现极简。
- **URL + 密码双重保护即权限**（v15）：密码生成后不做更改；没有账号体系。未来如建用户认证体系再整体替代本机制。

## 看板与容量

- **多看板 = 极简数据库管理**（v15）：看板列表仅增/删/打开，每板唯一 URL（`/b/:id`），删除须重输该板密码、物理删除不可恢复。
- **卡片上限 2000 硬 / 1500 软**（v16）：硬上限由服务端、CLI、页面三处共同拒绝；≥1500 起顶栏提示「按时间切片新建看板」并倒计时剩余容量。

## 时间轴与导航

- **滑动窗口 ±30 天**（v16）：以视口中心 ±30 天恒定加载 61 列（真实维度一年、日均约 5 张卡，性能有保障）；窗口外卡片仍在数据中，经 minimap/详情页改期抵达。
- **minimap 全局缩略导航**（v17 定形）：起点 = 第一张卡日期、终点 = 最后一张卡日期；红点 = 今天；高亮 = 已加载窗口（±30 天）；未加载区域压暗（dimming）；卡片分布用 1~3 点密度表示；拖框实时跟随重建（框先行，transform 直写）。
- **键盘导航**（v16）：`T` 回今天、`←/→` ±7 天、`Shift+←/→` ±30 天；输入框聚焦时不触发。

## 数据与导入

- **CLI 导入差分更新**（v13 产品目录 / v14 成员）：导入卡片含新产品/新成员时，对产品、成员目录做差分合并——同 id/同名复用更新、新条目追加、未提及保留、**永不删除**（删除只走页面管理入口）。
- **降级保护**（v11 产品 / v14 成员）：产品或成员被删除、或引用 id 匹配失败时，卡片显示「不明」/「未分配」而不崩溃——目录操作永远不能 degrade 卡片渲染。
- **产品名历史**：内置演示产品曾用「P1000 拾光轴」，后改名「光轴」（P-1000）；假产品名现已全部清除，当前内置目录仅此一项。

## 工程结构

- **monorepo 分包（v19，2026-09）**：不拆多仓库，单仓 npm workspaces 四包（core 契约 / server / cli / web）；core 以 `.ts` 源码经 workspaces 软链 + strip-types 零构建直引三端。
- **拖拽碰撞检测 = 组合式判定**（v19，2026-09-04）：pointerWithin 锁列 + 列内 closestCorners + 非源列排除拖拽卡自身。根因：全局 closestCorners 按角距判定，被拖拽卡自身 rect（钉在原列）截胡——实测指针深入邻列 30% 时自身赢下 82/86 次判定，目标列从不高亮。**不得回退为单一全局判定**（回归锁：e2e t57）。
- **Agent API（v18）**：item 级读写 + 逐字段审计（audit_log）+ 每板每 IP 120 次/分钟限速；鉴权与人类访问同口径（URL + 密码换 token），不另设密钥体系。
- **Agent PATCH 规则唯一定义在 core**（v20，2026-09-04）：白名单校验/指标联动/负责人解析/跨日 orders 更新下沉 `packages/core/lib/patch-core.ts`（applyItemPatch 纯函数），server 的 PATCH 路由只保留 HTTP/鉴权/审计/限速薄调用。已知差异（非 bug）：web BoardPage 按 patch 时点判定指标 gate，core 按最终态判定（更严）；web MemberManagerDialog 的 nextMemberId 与 core 重复，留作后续下沉项。
